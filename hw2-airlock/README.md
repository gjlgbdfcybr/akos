# ДЗ 2. Шлюз космической станции

Сборка и запуск в Linux или Ubuntu WSL:

```sh
make
./airlock input.txt run.log
```

Лог должен иметь новое имя: существующий файл программа не перезаписывает.
Ctrl+C или SIGTERM прекращает обслуживание, закрывает двери и завершает все потоки.
Люди, оставшиеся в камере, отражаются в итогах; автоматического спасения нет.

Первая строка входного файла:

```text
вместимость воздух энергия время_двери_мс время_давления_мс процент_отказа seed группы приоритет
```

Приоритет: 1 включает преимущество аварийного возвращения, 0 отключает его.
Группы: 1 — набирать ожидающих одного направления до вместимости, 0 — по одному.
Следующая строка — число людей (1–64), далее по строке на человека:

```text
id направление задержка_заявки_мс аварийный_приоритет
```

Направление: 0 — со станции в космос, 1 — из космоса на станцию.
Приоритет: 0 или 1; аварийный приоритет допустим только при возвращении.
Уже начатый проход не прерывается ради следующей заявки.

Начальное состояние: пустая камера, закрытые двери, нормальное давление.
Действие двери расходует 1 единицу энергии, изменение давления — 3;
восстановление нормального давления дополнительно расходует 5 единиц воздуха.
Перед посадкой проверяются ресурсы на весь проход группы.
Отказы моделируются перед операцией оборудования; аварийное закрытие считается исправным.

Главный поток — диспетчер. Каждый человек, каждая дверь и система давления имеют
собственный поток. Общие данные и вывод защищены мьютексом; команды, подтверждения
и уведомления о заявках передаются семафорами. Ожидание операции происходит без
удержания мьютекса. При остановке ожидающие потоки пробуждаются и присоединяются.

Вместимость ограничена 16, число людей — 64.

Основа — итоговое первое ДЗ из /home/matvey/akos/airlock в WSL.
Файл airlock.c перенесён без изменений: проверки дверей, перемещения людей,
давление и расчёт ресурсов остаются прежними. В person.h сохранены состояния
и направления, добавлены данные потоков и семафоры; arrival_tick заменён на arrival_ms.
Счётчик тиков Operation удалён, признак активности сохранён.
Диспетчер в dispatcher.c теперь посылает команды потокам и ждёт подтверждений.
main.c управляет запуском и завершением, config.c читает файл, output.c ведёт журнал.
Статусы заявок: not arrived, waiting, interrupted, done.

Число потоков: число людей + 4, включая главный. Планирование потоков влияет на
состав групп и порядок одновременных заявок: одинаковый seed не гарантирует
полностью одинаковый журнал. Программа возвращает 0 при полном выполнении,
1 при остановке или ошибке. Длительности оборудования допускаются от 1 до 60000 мс,
задержки заявок — от 0 до 3600000 мс. Параметры меняются во входном файле.
