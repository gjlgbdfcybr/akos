# ДЗ №4.

Linux, C17, TCP/IPv4. Сервер хранит состояние шлюза и очередь, моделирует двери и давление. Отдельный клиент представляет одного человека и подтверждает команды входа и выхода. Наблюдатель показывает общую картину.

## Сборка и запуск на одном компьютере

В Ubuntu/WSL:

```bash
cd /mnt/d/Develop/study/university/se/акос/HW/hw4-airlock
make
./server 127.0.0.1 9000 input.txt run.log
```

В другом терминале из той же папки сначала запустить наблюдателя:

```bash
./observer 127.0.0.1 9000
```

В третьем терминале запустить клиентов для трёх людей из примера:

```bash
./client 127.0.0.1 9000 1 &
./client 127.0.0.1 9000 2 &
./client 127.0.0.1 9000 3 &
wait
```

Наблюдателей можно запускать в нескольких терминалах. Наблюдатель не нужен для работы модели. Имя лога при каждом новом запуске должно быть новым: существующий файл не перезаписывается.

## Запуск по сети

Сервер: `./server 0.0.0.0 9000 input.txt run.log`. На другом Linux-компьютере клиент и наблюдатель запускаются с доступным IPv4-адресом компьютера сервера вместо 127.0.0.1. Порт должен быть доступен в сети. Для WSL доступ с другого компьютера зависит от настроек сети WSL и брандмауэра Windows. Приложения не используют общие файлы или общую память: input.txt нужен только серверу.

## Переподключение и остановка

Клиента можно остановить Ctrl+C, затем запустить снова с тем же ID. Сервер сохраняет заявку и местоположение человека в своей памяти. Если отключение произошло перед подтверждением перемещения, группа ждёт клиента. После его возвращения сервер повторно выдаёт ту же команду. Номер команды защищает от повторного выполнения одного перемещения. Пока группа ждёт, сервер продолжает принимать соединения наблюдателей и других клиентов. Вне активной группы отключённый клиент не мешает обслуживать подключённых.

Переподключение выполняется повторным запуском программы, не автоматическим циклом. Одновременно разрешено одно соединение на ID человека. Неизвестный ID и второе соединение для занятого ID отклоняются.

Наблюдатель может отключаться и подключаться независимо. При подключении получает снимок состояния шлюза и всех людей, затем новые события. История до подключения хранится в логе сервера.

После выполнения всех заявок сервер отправляет STOP оставшимся подключённым программам и завершается. Клиент человека может завершиться раньше по DONE. Ctrl+C и SIGTERM сервера закрывают двери, сохраняют итог в лог, отправляют STOP и закрывают сокеты. Если сервер аварийно завершён, клиенты выходят после обнаружения закрытия TCP. Сохранение состояния после перезапуска сервера и восстановление при SIGKILL не реализованы. При исчезновении компьютера из сети обнаружение разрыва зависит от TCP ОС.

Если человек не запущен или отключён и не возвращается, сервер ждёт; остановить ожидание можно Ctrl+C. При отказе оборудования или нехватке ресурсов симуляция прекращается. Уже вошедшие люди могут остаться в закрытом шлюзе, что отражается в итоговом состоянии.

## Входные данные

Первая строка:

```text
capacity air energy door_ms pressure_ms failure_percent seed grouped priority
```

Вместимость 1–16, запасы воздуха и энергии 0–2147483647, длительности операций 1–60000 мс, вероятность отказа 0–100, seed 0–2147483647, режим группы и приоритета 0 или 1.

Следующая строка — число людей 1–64. Далее для каждого:

```text
id direction arrival_ms emergency
```

ID положительный и уникальный. Направление 0 — со станции в космос, 1 — обратно. Время заявки 0–3600000 мс от запуска сервера; заявка становится доступной, когда это время наступило и клиент подключён. Emergency 1 разрешён только для возвращения на станцию. Приоритет выбирает экстренные заявки раньше обычных, затем более ранние заявки и меньшие ID. Группа набирается из уже доступных подключённых людей одного направления; ожидания заполнения группы нет.

Открытие или закрытие двери расходует 1 энергию, изменение давления — 3 энергии, повышение давления дополнительно расходует 5 воздуха. Перед проходом проверяются ресурсы на полный цикл. Вероятность отказа относится к изменяющим состояние операциям оборудования; аварийное закрытие выполняется без случайного отказа.

## Вывод и устройство

EVENT содержит миллисекунды от запуска сервера. STATE показывает общую сводку, PERSON — состояние человека. Для дверей 0 означает закрыто, 1 — открыто; для давления 0 — низкое, 1 — нормальное. Итог включает проверку безопасности, число людей внутри и состояние дверей. Общий вывод предназначен наблюдателям, клиент получает события только своего человека. Лог сервера содержит события всей модели.

Сервер использует один цикл poll и неблокирующие сокеты. Длительности операций отсчитываются CLOCK_MONOTONIC, без блокировки обработки сети. TCP-протокол текстовый, сообщения разделены переводом строки; обработаны неполные чтения и записи. Для медленного получателя есть ограниченная очередь вывода: при её заполнении отключается только это соединение. Максимум 128 одновременных соединений. Неопознанное соединение закрывается через 5 секунд.

Файлы: server.c — сеть и диспетчер; client.c — клиент и наблюдатель; net.c/net.h — общие функции TCP; config.c/model.h — вход и состояние модели; airlock.c/airlock.h/person.h — правила шлюза и структуры.

Реализованы TCP-взаимодействие, отдельный наблюдатель, несколько динамически подключаемых наблюдателей, повторное подключение клиентов с сохранением серверного состояния и завершение клиентов при остановке сервера.
